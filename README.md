# AVPlayer never posts DidPlayToEndTime after the subtitle option is deselected and the player seeks

A minimal app for macOS and iOS/iPadOS that reproduces the bug. It bundles a 300 s HLS VOD (`Media/content/`, generated by `gen.sh`) and serves it from an HTTP server on 127.0.0.1 inside the app, so it needs no network connection. The SUBTITLES rendition is a WebVTT playlist with one segment (`#EXTINF:280`).

## Steps

`Repro.swift` does the following:

1. Plays the item with `preferredForwardBufferDuration = 10` and selects the subtitle option.
2. After 2 s, calls `item.select(nil, in: legibleGroup)`. Only `-mode bug` does this; `-mode subon` skips it.
3. After 1 more s, calls `seek(to: duration - 20 s, toleranceBefore: .zero, toleranceAfter: .zero)`.
4. Waits 35 s, prints `RESULT <mode> ended|stalled`, and exits 0 (ended) or 1 (stalled).

## Build and run

macOS:

```
xcodebuild -project HLSLegibleStall.xcodeproj -scheme HLSLegibleStall -configuration Release -destination 'platform=macOS' -derivedDataPath build CODE_SIGN_IDENTITY=- build
build/Build/Products/Release/HLSLegibleStall.app/Contents/MacOS/HLSLegibleStall -mode bug
build/Build/Products/Release/HLSLegibleStall.app/Contents/MacOS/HLSLegibleStall -mode subon
```

iOS/iPadOS. Set your team. If your provisioning profile does not cover `dev.repro.HLSLegibleStall`, add `PRODUCT_BUNDLE_IDENTIFIER=<an id it covers>` to the build and launch with that id.

```
xcodebuild -project HLSLegibleStall.xcodeproj -scheme HLSLegibleStall -configuration Release -destination 'generic/platform=iOS' -derivedDataPath build -allowProvisioningUpdates DEVELOPMENT_TEAM=<team id> build
xcrun devicectl device install app --device <device id> build/Build/Products/Release-iphoneos/HLSLegibleStall.app
xcrun devicectl device process launch --console --device <device id> dev.repro.HLSLegibleStall -- -mode bug
xcrun devicectl device process launch --console --device <device id> dev.repro.HLSLegibleStall -- -mode subon
```

## Expected result

Both modes print `RESULT <mode> ended`: `AVPlayerItem.didPlayToEndTimeNotification` is posted at the end of the media.

## Actual result

`-mode bug` prints `RESULT bug stalled currentTime=299.92`. Playback stops 0.08 s before the end of the 300 s media, `playbackStalledNotification` is posted, and `didPlayToEndTimeNotification` never arrives. `-mode subon` prints `RESULT subon ended`.

| Platform | `bug` | `subon` |
|---|---|---|
| macOS 26.7.2 (25G332), Mac17,2 | stalled 3/3 | ended 2/2 |
| iPadOS 26.5 (23F77), iPad mini (6th generation) | stalled 2/2 | ended 2/2 |

Unified log of `-mode bug` on macOS (`log stream --level debug --predicate 'process == "HLSLegibleStall"'`, object addresses removed). Substream 0 is video, 1 is audio, 2 is subtitles. Video and audio report end of stream after the seek, but `At end of all streams` is never logged:
